# LifeLook ADU Construction and Financial Effects Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Model building an ADU on an existing California primary home and compare its funding, rental income, taxes, value, equity, and household cash flow with leaving that home as-is.

**Architecture:** An optional property-owned project supplies dated cost, financing, value, tax-payment, and capital movements. Pure schedulers feed the existing monthly projection and four rental tax books; a separate comparison calculates a validated selected-project no-build counterpart. The existing property draft bundle and scenario sessions own editing, previews, and persistence.

**Tech Stack:** Existing TypeScript, decimal.js, native HTML/CSS/SVG, localStorage, Vite, Vitest/jsdom, Playwright Chromium, and Node >=22. No new runtime dependencies.

**Spec:** [ADU construction, valuation, and rental cash flow](../specs/2026-10-13-lifelook-adu-build-design.md). Read both documents; this plan defines implementation interfaces, not a replacement financial contract.

## Global Constraints

- Keep embedded plan schema version 1 and the workspace envelope unchanged.
- Support one new, ordinary long-term, fair-market rental ADU per eligible primary home.
- A property with a planned project cannot also contain an existing ADU or another rental unit in this first version.
- Different eligible properties may each have a project; the selected project's comparison leaves other projects applied.
- The four central quantities are separate: **cash construction cost**, **added market value**, **added property-tax assessed value**, and **depreciable building basis**.
- The existing home and ADU remain one market-value asset; the ADU has separate rental tax books.
- Draws and planned construction payments cannot follow completion in this first version.
- Loan proceeds increase cash and debt equally; never present them as earned income or rent.
- For investment allocation, subtract only the owner-funded part of staged construction costs from income available for investing.
- Monthly funding ceilings use unrestricted household cash, excluding unspent project-earmarked proceeds.
- Tax depreciation reduces adjusted basis, not market value, equity, or cash directly.
- Before readiness, the capital ledger is not depreciable recovery basis.
- Existing provisional tax tables/California assumptions retain their labels.
- Expected values must be transcribed from independent arithmetic/source worksheets, not generated by production calculators.
- Export applied project inputs only; exclude comparison results, preview state, and drafts.
- When no project is present, every existing financial fixture retains its original result.
- Preserve the unsupported cases enumerated in the spec, including existing-building conversion, sales/recapture, mortgage replacement, variable-rate HELOCs, and unpaid interest added to principal.
- Local commits are permitted. Before any `git push`, obtain explicit user confirmation for the exact repository, remote, and branch.

## Review Focus

- A huge unrelated expense plus prospective project overrides must not break independent wage recovery by validating a filtered, dangling-reference plan; Task 6 tests runtime stream selection.
- A $100,000 draw reserved for a future payment plus $500 interest must show $99,500 total cash, −$500 unrestricted cash, and a $500 funding need; Tasks 3 and 6 pin this distinction.
- Pre-readiness deductions spanning a year boundary must retain four-book losses/risk when depreciation starts, without adding capital twice; Task 5 pins the transition.
- Missing primary-home area with direct valuation must preserve known value and explicitly personal mortgage deductions, while only default shared allocations need data; Tasks 1, 4, and 5 pin this locality.
- A→B→A project selection or scenario switching away/back at the same input revision must reject old worker replies; Task 9 pins project, activation, and request authority.

interface AduProject {
  id: string; name: string; rentalId: string;

All interface properties/rows are readonly in production. Unknown treatment preserves cash but leaves relevant tax fields unavailable. Known split amounts must sum to the associated paid cost/interest/tax amount. `taxQualifications` distinguishes confirmed supported treatment from known-unsupported or unknown treatment. Finance fees/other special recovery components remain unsupported when no ordinary building treatment is qualified; categorizing a fee as building cannot bypass qualification.
